The problem: passing data through every level

The cart count lives in App. The button and the badge are far apart, so the count travels through components that don't even use it.

The fix: keep shared data in one store

Redux puts shared data in a store outside the component tree. Any component can send an update to it, and any component can read from it.

Think of the college notice board

Students don't scribble on the board. They give a request slip to the office, the office decides, and the board is updated. Everyone reads the same board.

One trip around the Redux loop

Data only moves in one direction. That's what makes Redux apps easy to follow and debug.

  • 1User clicks a button in the View.
  • 2An action is dispatched: { type: "cart/add" }
  • 3The reducer works out the new state: 2 → 3
  • 4The store saves it and tells every component that reads it.
  • ✓The View re-renders with the new value.

    

  







  

    
Redux has 3 simple rules
Follow these and your app's data is always predictable.

    
  

  

    

      
One store for the whole app
All shared data lives in a single place. One source of truth.

      
✓ store.getState()
✗ copies of the cart in 5 components

    

      
State is read-only
Components never change the store directly. They dispatch an action instead.

      
✓ dispatch(addItem(7))
✗ store.cart.count = 5

    

      
Reducers are pure functions
Same state + same action = same result, every time. No side effects.

      
✓ return { count: state.count + 1 }
✗ fetch() or Math.random() inside

    Recap and a quick check
    
  
    
    
      
      
    • 🏪Store: one place for shared app data.
      • 
      
    • 📝Action: an object saying what happened. Sent with dispatch.
      • 
      
    • ⚙️Reducer: old state + action → new state. Pure, no side effects.
      • 
      
    • 👀useSelector reads from the store, useDispatch sends actions.
      • 
      
    • 🌐Client sends a request (GET, POST, PUT, DELETE), server sends a response with a status code.
      • 
      
    • ⏳Store the request status so the UI can show loading and errors.
