Chapter 1

Meet React

What it is, why people love it, and when to use it.

Chapter 1: no code yet, just ideas.

The problem React solves

😓

Without React

You change some data. Then YOU must find every place on the page that shows it and update each one by hand. Easy to forget one!

😎

With React

You change the data. React updates the page for you, automatically. You only describe what the screen should look like.

📊

Think of an Excel sheet: change one number and the TOTAL updates by itself. React does the same for web pages.

In jQuery we update the DOM by hand. React flips it: update the data, React updates the screen.

Two ways of thinking: jQuery vs React

Imperative: tell HOW, step by step

script.js
// jQuery: you do every step
let count = 0;
$("#btn").click(function () {
count = count + 1;
$("#num").text(count); // update by hand
});

Declarative: describe WHAT you want

Counter.jsx
// React: describe the screen
const [count, setCount] = useState(0);
<button onClick={() => setCount(count + 1)}>
{count}
</button> // React updates it
🍽️

Like ordering food: jQuery = cooking it yourself step by step. React = telling the waiter what you want.

You already know jQuery. Imperative means step-by-step instructions. Declarative means describing the result.

So, what is React?

React is a JavaScript library for building user interfaces using components.

🧰

Library

A toolbox of ready-made code you add to your project.

🖥️

User interface

Everything people see and click: buttons, forms, lists.

🧩

Components

Small reusable pieces that join to make a full page.

Three key words: library, user interface, components. React only handles the view: what the user sees.

The React story in 5 moments

2011Created at Facebook by Jordan Walke
2013Released free and open source
2015React Native for mobile apps
2019Hooks arrive (React 16.8)
2024React 19 released
React is not new: it has been improved for over 10 years, which is why it is so stable and popular.

Why do people choose React?

🧱

Reusable pieces

Build a button or card once, use it everywhere.

⚡

Fast updates

The Virtual DOM changes only what really changed.

🧠

Easy to start

If you know HTML and JavaScript, you can learn React.

🌍

Huge community

Used by apps like Instagram, Netflix and Airbnb. Lots of jobs and help online.

React vs React.js vs React Native

React = React.js = ReactJS. Same thing, just nicknames!
NameWhat it isRuns on
⚛️ ReactThe library for building user interfacesWeb browsers
📛 React.js / ReactJSNickname for React (".js" = JavaScript)Web browsers
📱 React NativeA DIFFERENT tool using React ideas for phone appsAndroid and iOS
Students often think React and React.js are different. They are the same. React Native is the separate one.

Library vs Framework

🧰

Library (React)

YOU are in control. You pick React for the UI, then add other tools (router, forms) as you need them.

🏗️

Framework (Angular)

The framework is in control. Everything comes included, and you follow its rules.

🧩

Library = buying separate LEGO sets you choose. Framework = a full ready-made LEGO city kit with a fixed plan.

When should you choose React?

✅ Choose React when...

✓

The page changes a lot when users click or type

✓

The same UI pieces repeat (cards, lists)

✓

You want an app feel with no page reloads

✓

You want skills companies hire for

🤔 Maybe skip React when...

−

It's a simple page with little interaction

−

It's a tiny script or one small form

−

It's a content site needing top Google ranking (use Next.js, built on React)

How React works inside

The DOM, the Virtual DOM and the React flow.

Chapter 3: behind the scenes.

First: what is the DOM?

The DOM (Document Object Model) is the browser's tree of everything on the page. JavaScript changes the page by changing this tree.

html
body
h1
p
button
🐢

Updating the real DOM again and again is SLOW, like repainting a whole wall to fix one small spot.

The Virtual DOM: React's smart copy

A light copy of the page kept in memory. React plays spot the difference, then fixes only the differences.

Virtual DOM in 4 steps

1State changescount goes 0 → 1
2New Virtual DOMA new copy in memory
3DiffingCompare old vs new
4ReconciliationUpdate only what changed
📝

Exam words: Diffing = comparing the two virtual trees. Reconciliation = updating the real DOM to match.

Real DOM vs Virtual DOM

🐢 Real DOM⚡ Virtual DOM
What is it?The actual page in the browserA copy of the page in memory
Speed to changeSlowVery fast
UpdatesCan redraw big partsOnly the changed parts
Who handles it?The browserReact
Real lifeRebuilding the whole houseChecking the blueprint first

The React flow: one-way data loop

1. Statethe data your app remembers
2. RenderReact draws the UI
3. Eventuser clicks or types
4. setStateyour code updates the data

Round and round.
Data flows ONE way 🔁

The heart of React. You never touch the screen directly: you change state, React re-renders.

What makes a component re-render?

"Re-render" = React runs your component function again to draw the new screen.

🧠

Its state changes

You called setCount, setName...

📦

Its props change

The parent sent new data.

👨‍👧

Its parent re-renders

Children redraw with the parent.

⚠️

Changing a normal variable (let x = 5) does NOT re-render. Only state changes do!

Props go DOWN, events go UP

Appholds the state: count
Displayshows the count
Button+1

props: count

props: onAdd()

event: clicked! calls onAdd()

Solid arrows: props go down. Dashed arrow: the child calls a function from the parent, which updates the parent's state.

Component life cycle: born, grows, leaves

🌱MountComponent appears on screen for the first time
🔄UpdateState or props change, it re-renders
🍂UnmountComponent is removed from the screen
Timer.jsx
useEffect(() => {
console.log("Mounted! 🌱");
return () => {
console.log("Unmounted! 🍂"); // cleanup
};
}, []);
🧹

The function you return from useEffect is the cleanup. It runs when the component leaves. Use it to stop timers.

Hooks

Chapter 4: the most important modern React feature.

What are Hooks?

Special functions that let a component remember things and do things. Names always start with use.

🧠

useState

Remember a value

⏰

useEffect

Do something after showing

🎯

useRef

Grab an element

🌐

useContext

Share data everywhere

📏

2 rules: (1) call hooks at the TOP of your component, never inside if or loops. (2) only inside React components.

useState: the memory of a component

const [count, setCount] = useState(0);
🔵

count

The current value. Read it to show on screen.

🟠

setCount

The function to change it. React then re-draws.

🩷

useState(0)

The starting value is 0.

⚠️

Never write count = 5. Always use setCount(5), or the screen won't update!

The square brackets are array destructuring: useState gives back two things.

Example: a counter with useState

Counter.jsx
import { useState } from "react";
function Counter() {
const [count, setCount] = useState(0);
return (
<div>
<h1>Count: {count}</h1>
<button onClick={() => setCount(count + 1)}>+1</button>
<button onClick={() => setCount(count - 1)}>-1</button>
<button onClick={() => setCount(0)}>Reset</button>
</div>
);
}
1️⃣

onClick runs

It calls setCount(count + 1)

2️⃣

State updates

React saves the new count

3️⃣

Re-render

The screen shows the new number

Your turn: click the counter!

It plays by itself. Click any button to take control 👆

Let a student come and click. Point at the state box changing before the screen.

useEffect: do something after the screen shows

useEffect
useEffect(() => {
// code to run
}, [dependencies]);

For side effects: fetching data, timers, changing the page title.

🎬

Like saying: "After you finish drawing, THEN do this."

Dependency listWhen does it run?Good for
[ ] emptyOnly ONCE, when it first showsFetching data
[count]Every time count changesUpdating the title
(no list)After EVERY renderRarely needed

Fetching a fake API: part 1, get the data

Users.jsx
import { useState, useEffect } from "react";
function Users() {
const [users, setUsers] = useState([]);
const [loading, setLoading] = useState(true);
useEffect(() => {
fetch("https://jsonplaceholder.typicode.com/users")
.then((res) => res.json())
.then((data) => {
setUsers(data);
setLoading(false);
});
}, []);
📦

2 states

users starts empty, loading starts true.

⏰

useEffect + [ ]

Runs once, when it appears.

🌐

fetch → json → set

Ask the server, read JSON, save it.

jsonplaceholder is a free fake API for practice. Same fetch() as our AJAX lesson, now inside useEffect.

Controlled input: React holds the value

1. User types "R"a key is pressed
2. onChange runssetName("R")
3. State updatesname = "R"
4. Input shows itvalue={name}

The state is the boss 👑
The input shows what state says

Example: a simple sign-up form

SignupForm.jsx
import { useState } from "react";
function SignupForm() {
const [name, setName] = useState("");
function handleSubmit(e) {
e.preventDefault(); // stop page reload
alert("Hello, " + name + "!");
}
return (
<form onSubmit={handleSubmit}>
<input
value={name}
onChange={(e) => setName(e.target.value)}
/>
<button type="submit">Send</button>
</form>
);
}
🔗

value={name}

The input shows the state.

⌨️

onChange

Runs on every key. e.target.value = what was typed.

🛑

e.preventDefault()

Stops the page reload. Same as jQuery!

Watch the form work

Each key press → onChange → setName → the input shows the new value.

Many inputs? Use one state object

Signup.jsx
const [form, setForm] = useState({ name: "", email: "" });
function handleChange(e) {
setForm({ ...form, [e.target.name]: e.target.value });
}
<input name="name" value={form.name} onChange={handleChange} />
<input name="email" value={form.email} onChange={handleChange} />
🗂️

One object

All fields live together in form.

🏷️

name attribute

Tells us WHICH field changed.

📋

...form

Copies old values, then changes one.

The spread operator ...form copies all old fields. [e.target.name] picks the field by its name.

Routing: many pages, no reloads

A router looks at the URL and decides which component to show.

React doesn't include one. We add the popular one:

Terminal
npm install react-router-dom
🛎️

Like a receptionist who sends you to the right room.

URL: /
<Home />
URL: /about
<About />
URL: /contact
<Contact />

React Router in code

App.jsx
import { BrowserRouter, Routes, Route, Link }
from "react-router-dom";
function App() {
return (
<BrowserRouter>
<nav>
<Link to="/">Home</Link>
<Link to="/about">About</Link>
</nav>
<Routes>
<Route path="/" element={<Home />} />
<Route path="/about" element={<About />} />
</Routes>
</BrowserRouter>
);
}
🔌

BrowserRouter

Turns routing ON. Wrap the whole app.

🗺️

Routes + Route

Which component for which URL.

🔗

Link

Like <a>, but with no page reload.

Watch React Router switch pages

The URL changes, the matching Route is picked, and the reload counter stays at 0.
